# 用户规模口径（2026-11-23 实测）

> 一句话结论：**没有任何一个数字能同时回答"多少用户"和"多少活跃用户"。
> 我们手上最好的口径是「当前版本每周 tarball 下载数 − 爬虫底噪」，
> 约 **300–420 / 周**；横向落在 DSH 插件市场的 **75 分位**。**
>
> 本文所有数字都是 2026-11-23 现拉的，命令和出处逐条写在下面，可复算。

## 二、每个数字怎么失真

### npm 下载量

npm 官方口径（[numeric precision matters](https://blog.npmjs.org/post/92574016600/numeric-precision-matters-how-npm-download-counts-work.html)）：
**下载数 = tarball 的 HTTP 200 次数，naïve by design**。CI、镜像、安全扫描器全算；
同一个人重装 / 换版本会重复算；**卸载完全看不见**。
所以它是"安装事件数"，**不是用户数**。

### 本包的爬虫底噪（实测得出）

`versions/last-week` 里 54 个版本，除 0.5.3（409）外：

- **44 个版本恰好各 2 次**
- 5 个版本各 1 次
- 合计 **93 次 = 过去 7 天总下载的 18%**

这种"均匀到每个历史版本各 2 次"的分布只可能是自动化扫描器每周把所有版本拉一遍
（npm 打点无去重，见 [tarball GET 计数实验](https://www.npmjs.com/package/tj-npm-downloads-test)）。

> 注意：这个底噪是**本包专属**观测。对照组 `chalk` / `is-number` 的老版本是 65 / 1 次量级，
> 不能用它们的比例外推（流行包老版本有真实回流）。

### 发布期虚高（必须剔除）

| 日期 | 下载 | 原因 |
|---|---|---|
| 10-17 | 548 | 首发（当天发 3 个版本） |
| 10-18 | **4,682** | 当天连发 **27** 个版本 + 作者反复自装 |
| 10-21 ~ 10-25 | 440 ~ 570 / 天 | 开发期自测（每天 1~2 个版本） |

10-17 到 10-25 共 9 天、约 8,000 次，**绝大部分是我们自己**。
把这个窗口剔掉，后面才是真实基线。

### 语音包下载更接近"真人动作"

下载语音包需要：进设置页 → 确认使用条款 → 手动点下载。
机器人不会做这一套。所以 1,262 次是**真人操作**的硬证据。

但它**不是人数**：同一个人可以下多个包（15 个包，平均每人 1~2 个较常见）。
它给的是**量级印证**，不是精确人数。

### `packs.json` 的 680 不能算

设置页每次打开都会 `fetchPackIndex()`（`lib/voice-pack-route.js:121`），
同一用户反复开设置页就反复计数。**明确剔除**。

## 三、最真实的口径（按可信度排序）

### 口径 A（推荐）：当前版本周下载 − 爬虫底噪

```
409 − ~2 ≈ 400 / 周
```

这是"本周有多少次真实安装/更新"的**上限**（仍含 CI 镜像与重装）。
保守区间 **300–420 / 周**。

### 口径 B：语音包 zip 下载（全周期 1,262）

独立来源的交叉验证。量级一致 ⇒ 确实有几百人真的装了、并在用设置页。
但包含多包下载，不能直接当人数。

### 口径 C：GitHub 侧痕迹（3 star / 3 个不同 issue 作者 / 14 天 65 独立访客）

唯一**天然去重**的信号，但只覆盖"愿意留下痕迹"的极小部分。
典型插件这个比例在 1~5%，反推同样是**几百人**量级。

### ❌ 不要用的口径

| 数字 | 为什么不能用 |
|---|---|
| 全周期 10,998 | 被发布日自测 + 早期开发期严重污染 |
| `packs.json` 680 | 同一人反复开设置页重复计 |
| Star 数（3） | DSH 生态 star 普遍偏低，awesome 页面排名用 star，3 star 说明不了装机 |

## 四、横向定位（这才让数字有意义）

抽样方法：从市场索引 `https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json`
（**6,554 个插件**，format 1）里定距抽 60 个，成功取到 40 个的 last-week。

| 分位 | 周下载 |
|---|---|
| min | 165 |
| p25 | 255 |
| **中位数** | **310** |
| p75 | 446 |
| p90 | 850 |
| max | 10,711（`@zilliz/memsearch-dsh`） |

**我们 514 / 周 ≈ 75 分位**（比 30/40 个抽样插件高）。

参照系：`@deepseek-ai/dsh` 本体同期 **66.3 万 / 周**，我们是它的 **0.08%**。

### 这个分位要打折看

抽样的 40 个插件**全部只有 1 个版本**——整个 DSH 插件生态才起来几个月，
大家都是刚发的第一版。所以 p75 的门槛并不算高。

**更值得看的是趋势**：

| 窗口 | 日均 |
|---|---|
| 10-26 ~ 11-08 | 159 / 天 |
| 11-09 ~ 11-22 | 84 / 天 |
| 11-16 ~ 11-22 | 73 / 天 |

在缓慢下滑。有发布热度自然消退的成分，但也说明**没有新的传播入口在持续带人**：
没做 README 截图、没在社区发过、star 只有 3。

## 五、原理上不可知的部分（诚实边界）

### 插件没有遥测，也不该有

`lib/` 全部外联只有三处：

| 地址 | 用途 |
|---|---|
| `registry.npmjs.org/dsh-notify-say` | 更新检查（`lib/update-check.js:47`） |
| `raw.githubusercontent.com/.../package.json` + CHANGELOG | 更新检查回退（`:51`、`:55`） |
| `github.com/.../releases/.../packs.json` + 各 zip | 语音包索引与下载（`lib/voice-pack-download.js:64`、`:68`） |

**没有任何 phone-home**。所以"活跃装机数"在原理上不可知，只能靠代理指标。
这是有意的设计选择，不要为了数字加遥测。

### 市场不统计安装数

`dshmarket.com/index.json` 的 6,554 条记录，`metadata.sortKeys` **全是空对象**
（实测：有数字 sortKeys 的条目 0 条）；`dshmarket` 的 lib 里也没有上报安装的请求。
**市场帮不了我们。**
